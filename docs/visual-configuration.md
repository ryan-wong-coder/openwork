# 可视化配置覆盖与验收

`visualConfiguration` 在功能注册表中默认关闭。个人本地客户端通过安装级功能锁启用；连接版和云端继续服从服务端的组织功能配置。Den 自托管部署可向进程注入 `DEN_FEATURE_VISUAL_CONFIGURATION=true`，或在 `/admin` 为组织开启。设为 `false` 可恢复原入口，已有配置仍保留。开发脚本不会自动加载任意命名的私有环境文件，须显式加载，且不得提交凭据。

| 用户维护的配置 | 可视化入口 | 覆盖与保存方式 |
| --- | --- | --- |
| 项目和全局 `opencode.json` / `opencode.jsonc` | 设置 → 高级 → 配置选项 | 枚举当前 OpenCode SDK 的全部 36 个顶层字段。提供方、模型、MCP、授权、权限、助手、技能来源、插件、指令、代码分析、格式化和实验参数均可逐项修改。未知字段使用递归类型控件，保留原有值。 |
| 工作区 `openwork.json` | 同一入口的工作区范围 | 工作区名称、预设、允许的目录、重新应用选项、模板、快捷操作和预置对话。保存完整用户文档，支持移除选项。 |
| 用户环境变量 | 设置 → 环境 | 沿用现有变量表格、密钥遮罩和应用流程。 |
| 桌面偏好 | 设置 → 偏好 | 沿用主题、语言和工作方式控件，并补充打开外部链接前询问。 |
| 本地模型网关与图片模型 | 设置 → 模型网关 | 网关地址、密钥、模型目录及图片模型由专用控件管理。实际请求和密钥持久化属于本地服务。 |
| Den 自定义提供商的高级配置 | AI 网关 → 自定义提供商 → 高级选项 | 所有对象、列表、联合类型和未知扩展参数均可递归编辑。支持导入 JSON / JSONC 文件、撤销导入及逐字段检查。 |
| Den 工作流输入、输入格式和返回格式 | 工作流 → 概览 / 编辑 | 现有简单输入表单继续使用；复杂结构和布尔、空值根节点使用递归控件。源代码保留代码编辑器。 |

引擎文件修改只作用于变动字段，保留未修改的注释、未知字段和类型；保存前检查原文件快照，服务端原子比较并拒绝冲突。工作区保存同样使用完整文档快照比较。无效文档不会被替换，冲突时草稿保留。Den 的配置本来以对象存储，导入后转为表单对象，不承诺保留导入文件的注释排版。

内部状态不作为可任意编辑的用户配置：配置版本、工作区创建时间、云同步与导入记录、模板物化记录、运行时数据库、注入的运行参数及组织管理策略保持原有来源和权限。它们不会因保存用户表单被清空。工具测试器的一次性调用参数、只读工具结果、Slack manifest 和服务账号凭据文件分别属于测试输入、诊断或凭据，不计为配置文件编辑入口。

验收遵循 `DESIGN.md` 的 P3（递进展开）、P5（复用控件）和 P8（可撤销）。已在 headless Chrome 中检查桌面项目 / MCP / 工作区范围，以及真实 Den 提供商和工作流页面的隔离响应夹具。Den 夹具只验证界面、序列化和交互，不代表已部署或已连通真实组织服务。桌面验收没有保存开发者的全局引擎配置。

```sh
pnpm --filter @openwork/app exec bun test tests/visual-config-document.test.ts tests/visual-config-view.test.tsx
pnpm --filter openwork-server exec bun test test/visual-config-api.test.ts
pnpm --filter @openwork-ee/den-web exec bun test tests/structured-config.test.tsx
pnpm --filter @openwork/app typecheck
pnpm --filter @openwork-ee/den-web typecheck
```

服务端测试使用隔离的临时配置目录，验证项目文件、全局文件和工作区文档的同基线并发写入只有一个成功、另一个返回冲突。表单测试验证快照、无效输入阻止保存、冲突保留草稿、数组和未知类型保留。
